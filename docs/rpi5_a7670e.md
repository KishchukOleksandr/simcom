# Raspberry Pi 5 & Waveshare A7670E Cat-1/GNSS HAT Example {#rpi5_a7670e_page}

This guide walks through setting up, building, and running the **libsimcom** reference application (`examples/rpi5_a7670e/`) on a **Raspberry Pi 5** equipped with the **[Waveshare A7670E Cat-1/GNSS HAT](https://www.waveshare.com/wiki/A7670E_Cat-1/GNSS_HAT#Features)**.

---

## 1. Hardware Overview & Jumper Configuration

### Required Hardware
- **Raspberry Pi 5** (running Raspberry Pi OS Bookworm or later) with a 5V/5A USB-C power supply.
- **Waveshare A7670E Cat-1/GNSS HAT** mounted onto the 40-pin GPIO header.
- **LTE Main Antenna** connected to the `MAIN` SMA connector on the HAT.
- **Activated nano-SIM card** inserted into the bottom SIM card slot.

### Yellow Jumper Configuration on the Waveshare A7670E HAT
Configure the yellow 2.54 mm jumper caps on the Waveshare HAT header block as follows:

| Jumper Pin | Connect To | Raspberry Pi 5 Pin | Purpose |
| :--- | :--- | :--- | :--- |
| **`PWR`** | **`D4`** | Pin 7 (`BCM GPIO 4`) | Routes `PWRKEY` control to Raspberry Pi GPIO 4 so the application automatically wakes the modem at startup. |
| **`RXD`** | **`TXD0`** (via default row) | Pin 8 (`BCM GPIO 14`) | Connects Raspberry Pi UART0 transmit to the A7670E receive line. |
| **`TXD`** | **`RXD0`** (via default row) | Pin 10 (`BCM GPIO 15`) | Connects A7670E transmit to the Raspberry Pi UART0 receive line. |

## 2. Raspberry Pi 5 OS Configuration

### Enable 40-Pin Header UART0 (`/dev/ttyAMA0`)
On Raspberry Pi 5, edit `/boot/firmware/config.txt` and ensure the primary header UART is enabled:

```ini
enable_uart=1
dtparam=uart0=on
```

Disable the Linux serial login console on `ttyAMA0` so it does not interfere with AT commands:
1. Run `sudo raspi-config`.
2. Navigate to **Interface Options** → **Serial Port**.
3. Select **No** for *"Would you like a login shell to be accessible over serial?"*.
4. Select **Yes** for *"Would you like the serial port hardware to be enabled?"*.
5. Reboot the Raspberry Pi 5 (`sudo reboot`).

### Grant Serial & GPIO Permissions
Add your Linux user account to the `dialout` (serial ports) and `gpio` (RP1 `/dev/gpiochip4` / `/dev/gpiochip0`) groups:

```bash
sudo usermod -aG dialout,gpio $USER
```

## 3. Building & Running the Example

From the repository root on your Raspberry Pi 5:

```bash
# 1. Configure CMake with examples enabled
cmake -B build -DCMAKE_BUILD_TYPE=Release -DSIMCOM_BUILD_EXAMPLES=ON

# 2. Build the library and Raspberry Pi 5 example executable
cmake --build build

# 3. Run in default mode (/dev/ttyAMA0, 115200 baud, GPIO 4 PWRKEY, continuous monitoring)
./build/examples/rpi5_a7670e/simcom_rpi5_a7670e
```

## 4. Command-Line Options

| Flag | Argument | Default | Description |
| :--- | :--- | :--- | :--- |
| `-p`, `--port` | `<path>` | `/dev/ttyAMA0` | Serial device path (e.g., `/dev/ttyAMA0` or `/dev/ttyUSB2`). |
| `-b`, `--baud` | `<rate>` | `115200` | UART baud rate (`9600`..`921600`). |
| `-g`, `--gpio-chip` | `<path>` | Auto (`/dev/gpiochip4` → `/dev/gpiochip0`) | Linux GPIO v2 character device path. |
| `-k`, `--pwrkey-pin` | `<num>` | `4` | BCM GPIO pin number wired to the HAT `PWRKEY` jumper. |
| `-P`, `--pin` | `<digits>` | None | Optional 4–8 digit SIM PIN code for PIN-locked SIM cards. |
| `-1`, `--once` | None | Off (continuous) | Exit immediately after printing the initial status report. |
| `-v`, `--verbose` | None | Off (`INFO`) | Enable `DEBUG`-level raw AT `[TX]`, `[RX]`, `[URC]`, and `[FSM]` logging. |
| `-q`, `--quiet` | None | Off | Suppress informational banners; print only warnings, errors, and the status report. |
| `-h`, `--help` | None | Off | Print CLI usage instructions and exit. |

### Common Invocation Examples

```bash
# Single-shot status summary with raw AT frame debugging enabled:
./build/examples/rpi5_a7670e/simcom_rpi5_a7670e --verbose --once

# Unlock a PIN-protected SIM card and monitor network registration:
./build/examples/rpi5_a7670e/simcom_rpi5_a7670e --pin 1234

# Connect over the Waveshare HAT USB Type-C port instead of 40-pin UART:
./build/examples/rpi5_a7670e/simcom_rpi5_a7670e --port /dev/ttyUSB2 --baud 115200
```

## 6. Troubleshooting

- **`MODEM_UNRESPONSIVE` Fault**:
  - Verify the yellow `PWR` jumper on the Waveshare HAT is placed across **`PWR` and `D4`**.
  - Check that the red `PWR` LED and `NET` LED on the Waveshare HAT illuminate after the startup GPIO 4 pulse.
  - Confirm `/dev/ttyAMA0` is enabled (`dtparam=uart0=on`) and `ModemManager` is not holding the port (`sudo systemctl stop ModemManager`).
- **`Cannot open GPIO character device`**:
  - Verify your user is in the `gpio` group (`groups $USER`) or run with `sudo`.
- **`SIM_REQUIRED` / `PIN_REQUIRED` Warning**:
  - Re-run with `--pin <your_4_to_8_digit_pin>` to unlock the SIM card using a single-shot `AT+CPIN` request.
